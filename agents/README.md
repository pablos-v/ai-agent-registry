# Агенты контура

Три специализированных агента. Каждый описан одним документом, который одновременно является
и его конфигурацией, и его должностной инструкцией.

## Почему агенты специализированные, а не один универсальный

- **Ограничение полномочий.** Агент базы знаний физически не имеет доступа к биллингу.
  Ошибка в одной зоне не превращается в изменение данных в соседней.
- **Плотность контекста.** Специфика одной системы помещается в конфигурацию целиком,
  без размывания на пять предметных областей.
- **Дешевле.** Рутинные агенты работают на быстрой модели; сложные архитектурные задачи
  поднимаются на уровень выше, к сильной модели.

## Единый формат конфигурации

```
--- метаданные ---
name          идентификатор для вызова
description   когда вызывать и, отдельно, когда НЕ вызывать
tools         разрешённый инструментарий (белый список)
model         класс модели под сложность задач агента
-------------------

# Роль

## Предохранители      ← читаются до любого действия: массовые операции, секреты, ПДн
## Контекст            ← что за система, границы зоны ответственности
## Инструменты         ← типизированные операции, разрешённые агенту
## Паттерны            ← типовые задачи и правильные способы их решать
## Запреты             ← что агент не делает никогда, даже по прямой просьбе
```

Блок предохранителей у всех агентов одинаковый — это сквозные политики контура
([policies/](../policies/)). Различаются контекст, инструменты и паттерны.
