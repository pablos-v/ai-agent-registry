# 02. Миграция учётных записей в корпоративный каталог

**Статус: выполнено разово**

## Задача

Перевести сотни сотрудников из учётной системы в корпоративный каталог пользователей:
создать учётные записи, разложить по организационным подразделениям, назначить группы
согласно ролевой модели, заполнить атрибуты.

Ручной ввод такого объёма — это недели работы и гарантированные опечатки в атрибутах,
которые потом всплывают как «у сотрудника не работает доступ».

## Схема

```
выгрузка источника (роли, подразделения, атрибуты)
   ↓
маппинг: роль в учётной системе → группа в каталоге (таблица соответствий, согласована с людьми)
   ↓
dry-run: сколько записей будет создано, десять примеров глазами
   ↓
пилот на нескольких записях → выборочная проверка человеком
   ↓
пакетное исполнение через MCP-коннектор к каталогу
   ↓
верификация: перечитать созданные записи и их членство в группах
   ↓
отчёт о расхождениях
```

## Что важно в реализации

- **Маппинг ролей — предмет согласования с людьми, а не догадка модели.** Таблица соответствий
  утверждается до запуска; всё, что не попало в неё, идёт в список исключений и разбирается руками.
- **Ритуал массовых операций** соблюдён полностью: фильтр, границы («кого не переносим»),
  счётчик, десять примеров, пилот, план отката.
- **Выборочная верификация после.** Проверялось не только «создалось», но и «те ли группы
  назначены» — на выборке записей.

## Результат

Сотни учётных записей перенесены с ролевым маппингом. Расхождения выявлены на этапе
верификации, а не через обращения сотрудников в поддержку.
