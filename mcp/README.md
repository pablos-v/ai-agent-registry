# Коннекторы

Коннектор — слой между агентом и системой. Агент не получает произвольный доступ:
он вызывает конечный набор типизированных операций. Это одновременно ограничение
радиуса поражения ошибки, единая точка логирования и место, куда встраиваются проверки.

Часть коннекторов реализована как MCP-серверы — тогда их можно переиспользовать
разными агентами и тестировать отдельно от агентов.

## directory-mcp — каталог пользователей (LDAP/Active Directory)

Написан мной, в ежедневной эксплуатации. Здесь опубликован с обезличенными значениями
по умолчанию: адрес каталога, домен и организационные подразделения заменены на примеры.

**Инструменты (все — только чтение):**

| Инструмент | Назначение |
|---|---|
| `ldap_search_users` | Поиск пользователей по имени, логину, атрибутам |
| `ldap_search_groups` | Поиск групп |
| `ldap_get_user_groups` | Членство пользователя в группах |
| `ldap_test` | Проверка подключения и учётных данных |

**Почему только чтение.** Создание и изменение учётных записей — мутирующая операция;
она идёт через агента с подтверждением человеком, а не напрямую из инструмента. Разделение
осознанное: коннектор, который умеет писать, рано или поздно вызовут «просто посмотреть».

**Учётные данные** сервисной учётной записи передаются переменной окружения и не хранятся
в конфигурации: `config.example.json` содержит всё, кроме пароля.
Сервисная учётная запись имеет права только на чтение каталога.

**Запуск:**

```bash
pip install -r requirements.txt
export LDAP_SERVICE_PASSWORD="..."   # из менеджера паролей, не из репозитория
python directory_mcp_server.py
```

Подключение к клиенту — как обычный MCP-сервер по stdio.

## Коннектор к таблицам (Excel)

Готовый MCP-сервер стороннего автора, подключён к контуру для задач выгрузки и подготовки
отчётных таблиц. Пример того, что не каждый коннектор нужно писать самому: если задача
типовая, дешевле взять существующий и ограничить область его применения.

## Прочие интеграции

Обращения к биллингу и ERP идут не через MCP, а через типизированные операции внутри агентов:
CLI биллинга, штатный SOAP/REST API систем и SQL в режиме чтения. Причина — эти операции
требуют предварительных проверок и подтверждения человеком, то есть логики,
которой место в агенте, а не в коннекторе.
